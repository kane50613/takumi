---
title: Use takumi in scripts
description: Pipe HTML in and images out, read the exit codes, and fail a build on a file a document cannot load.
---

`takumi` is built to sit in a pipeline. The rendered file is the only thing it writes to standard output, messages go to standard error, and the exit code tells a script what went wrong.

## Read from standard input

`-` as the input reads the HTML from standard input. Here `generate-card` stands for any program that prints HTML:

```sh
generate-card --title "Launch day" | takumi image - -o card.png
```

A document read from standard input gets no readable directory, since it has no file to sit beside. If it references stylesheets, images, or fonts, grant their directory with `--root`. Relative URLs then resolve against the working directory:

```sh
generate-card | takumi image - -o card.png --root assets
```

## Write to standard output

`-o -` writes the output to standard output. There is no file extension to read the format from, so an image needs `--format`. This example compresses the image with `gzip` on its way to a file:

```sh
takumi image card.html -o - --format svg | gzip > card.svg.gz
```

`takumi pdf` always writes PDF, so it needs no `--format`. Neither command writes binary output to a terminal. Redirect it to a file or a pipe.

## Messages and exit codes

Warnings and errors go to standard error, starting with `warning:` or `error:`. A warning means a file was skipped and the render went on, such as a missing image. `-q` hides warnings and keeps errors.

### What a render did

`--log info` prints one line to standard error for each stage, with the time since the command began:

```sh
takumi image card.html -o card.png --log info
```

```
[     0.6ms] input: read file:///site/card.html, 290 bytes
[     5.1ms] stylesheet: style sheets loaded: 1
[    10.2ms] resource: images loaded: 1
[    20.0ms] render: rendered 4339 bytes
[    20.1ms] output: writing card.png
```

`--log debug` adds a line for each style sheet, font file, and image loaded, the size layout gave the canvas or each PDF page, and what the render looked for and did not find:

```
[     3.9ms] font: no face is loaded for font-family "Inter"
[     5.8ms] image: no image is loaded for "missing.png"
[     6.0ms] layout: page 1 is 718.1102x1046.9292
```

A missing font family is not a warning, since text falls back to the next family as CSS says. The `debug` line is where it shows. Each `debug` line prints once, however many boxes reach it. The word before the colon is the stage, so `grep '] font:'` keeps one stage.

### Exit codes

The exit code tells a script why a render failed:

| Code | Meaning                                                                |
| ---- | ---------------------------------------------------------------------- |
| `0`  | The output was written, or the listing printed.                        |
| `1`  | The render failed. <sup>1</sup>                                        |
| `2`  | The command line is wrong. <sup>2</sup>                                |
| `3`  | The document tried to read a file outside the directories you granted. |

<sup>1</sup> For example, an input that does not exist, or a file past the size limits.

<sup>2</sup> For example, an unknown flag, a value CSS does not accept, or an output format takumi
does not write.

Code `3` separates a policy failure from a broken document, so a script can retry with `--allow-read`, or report the document as untrusted. See [Control file access](/docs/cli/file-access).

## Check a document in CI

`--list-resources` prints one tab-separated line for each file the document would load, with `allowed` in the second field for a file that would load. This step fails when any file would not:

```sh
listing=$(takumi image page.html --list-resources) || exit
unloaded=$(printf '%s\n' "$listing" | awk -F '\t' '$2 != "allowed"')

if [ -n "$unloaded" ]; then
  printf '%s\n' "$unloaded"
  exit 1
fi
```

## Render many files

Each run renders one file, so a shell loop covers a directory:

```sh
for page in pages/*.html; do
  takumi image "$page" -o "out/$(basename "$page" .html).png" --width 1200 --height 630 || exit
done
```

`|| exit` stops the loop at the first failure and keeps its exit code.
