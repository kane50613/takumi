Takumi is one layout engine, with text and inline layout ported from Chromium. It turns JSX, HTML, and CSS into images, PDFs, and other outputs without a headless browser.

## Pick a package

Each package runs the same layout engine. Pick the one that produces your output.

## Install

```npm
npm i takumi-js
```

`takumi-js` ships two backends and picks one at runtime. You install nothing else.

| Runtime                                           | Backend                         |
| ------------------------------------------------- | ------------------------------- |
| Node.js, Bun                                      | native (`@takumi-rs/core`)      |
| Cloudflare Workers, edge runtimes, Deno, browsers | WebAssembly (`@takumi-rs/wasm`) |

## Render an image

`render` takes JSX and returns encoded image bytes. Save this as `image.tsx` and run `bun image.tsx`. In Node.js, compile the JSX first.

```tsx twoslash title="image.tsx"
import { render } from "takumi-js";
import { writeFile } from "node:fs/promises";

const png = await render(
  <div
    style={{
      fontSize: 72,
      background: "linear-gradient(to bottom right, #fff7ed, #fecaca)",
    }}
    tw="w-full h-full flex items-center justify-center"
  >
    Hello Takumi
  </div>,
  { width: 1200, height: 630 }, // [!code highlight]
);

await writeFile("hello.png", png);
```

- `width` and `height` set the image size. Leave one out to size that side to the content.
- `tw="w-full h-full"` makes the root fill the image.

## Serve it over HTTP

[`ImageResponse`](/docs/image-response) extends the web `Response`. Return it from any route handler that uses `Request` and `Response`. Its API matches `next/og`.

```tsx twoslash title="app/og/route.tsx"
import { ImageResponse } from "takumi-js/response";

export function GET() {
  return new ImageResponse(<div tw="w-full h-full grid place-items-center">Hello Takumi</div>, {
    width: 1200,
    height: 630,
  });
}
```

<Callout type="warning">
  Takumi never reads system fonts. The only built-in font is Geist, which covers Latin at weights
  300 to 800. Load fonts for other scripts through `fonts`, or their glyphs go missing. See
  [Fonts](/docs/typography-and-fonts).
</Callout>

## Load a font

`googleFonts` loads Google Fonts families in one request. A weight range or an `axes` entry loads the variable font. Then `font-weight` and `font-variation-settings` set its axes per element.

```tsx twoslash title="Load a variable font"
import { render } from "takumi-js";
import { googleFonts } from "takumi-js/helpers";

const png = await render(
  <div
    style={{
      fontSize: 72,
      fontFamily: "Fraunces",
      // [!code highlight]
      fontVariationSettings: "'opsz' 72, 'wght' 700",
    }}
    tw="w-full h-full flex items-center justify-center"
  >
    Hello Takumi
  </div>,
  {
    width: 1200,
    height: 630,
    // [!code highlight:7]
    fonts: googleFonts([
      {
        name: "Fraunces",
        weight: "100..900",
        axes: { opsz: "9..144" },
      },
    ]),
  },
);
```

`fonts` also takes a font URL, raw bytes, or a descriptor. To load fonts before the first request, [register them on a `Renderer`](/docs/typography-and-fonts#preloading-with-registerfont).

## Coming from satori

A bare `<div>` lays out as a block, as in a browser. Keep explicit Flexbox styles when you move a Satori template, and compare the output. `renderSvg()` returns SVG like `satori()` does. `render()` returns encoded image bytes. See the [Satori comparison and migration guide](/docs/comparison-to-satori).
