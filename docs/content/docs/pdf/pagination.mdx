---
title: Pagination
description: Start pages where you want, keep related content together, and control how paragraphs and tables split across PDF pages.
---

Content lays out at the width inside the margins, then flows across pages. CSS break properties start chapters on a new page, keep related content together, and control how paragraphs split. The content has no fixed height, so percentage heights do not resolve, but viewport units do. `vh` is the height of the page area inside the margins, as in print.

## Mixed page sizes

Use `sections` to append content with a different page size or orientation in one `render()` call. Each section starts on a new page and paginates at its own content width and height. The PDF writes the physical size into each page's `MediaBox`; it does not rotate portrait pages or merge separate PDFs.

```tsx twoslash title="Portrait report with a landscape appendix"
declare const report: import("react").ReactNode;
declare const ledger: import("react").ReactNode;
// ---cut---
import { render, PageNumber, TotalPages } from "takumi-pdf";

const pdf = await render(report, {
  size: "a4",
  footer: (
    <div>
      Page <PageNumber /> of <TotalPages />
    </div>
  ),
  // [!code highlight:6]
  sections: [
    { node: ledger, landscape: true, margin: 32 },
    { node: <p>Closing note, back on portrait A4.</p> },
    { node: <p>Custom paper.</p>, size: { width: 600, height: 400 } },
  ],
});
```

Each section accepts `node`, `size`, `landscape`, `margin`, `header`, and `footer`. Omitted geometry fields inherit the **document options**, not the preceding section. `landscape: false` explicitly selects the unswapped size. A supplied `margin` replaces the whole margin setting. Explicit dimensions use CSS pixels, like the document's `size`.

Headers and footers inherit too; pass `false` to remove one for a section. Document `pages.first`, `pages.last`, `pages.odd`, and `pages.even` rules still override these bands using document-wide page numbers.

`PageNumber`, `TotalPages`, target-page counters, page ranges, internal links, the outline, metadata, attachments, and the tagged structure tree belong to the whole document. A section can contain JSX, HTML (including its stylesheet), or a node tree. Fonts, images, and CSS are shared across sections. Nonempty `sections` cannot be combined with `viewport`; an empty list is a no-op.

## Break properties

```tsx twoslash title="Break properties"
import { render } from "takumi-pdf";

const pdf = await render(
  <article>
    {/* [!code highlight:2] */}
    <h1 style={{ breakBefore: "page" }}>Chapter two</h1>
    <section style={{ breakInside: "avoid" }}>Keep this together.</section>
  </article>,
);
```

| Property                      | Effect                                                  |
| ----------------------------- | ------------------------------------------------------- |
| `break-before: page`          | Starts the element on a new page.                       |
| `break-after: page`           | Starts the following content on a new page.             |
| `break-inside: avoid`         | Keeps the element on one page when it fits.             |
| `box-decoration-break: clone` | Repeats borders and backgrounds on every page fragment. |

`break-inside: avoid` applies only when the box fits on a page. A taller box still splits. Boxes, floats, flex and grid items, and table rows break across pages, as Chromium prints them. A text line or an image never splits. It moves to the next page, and when it is taller than a page it runs on over the pages after it.

## Full-page boxes

A `100vh` box fills the page area, so the next box starts on the following page. That suits a cover or any page laid out by hand:

```tsx twoslash title="Full-page cover"
import { render } from "takumi-pdf";

const pdf = await render(
  <article>
    {/* [!code highlight] */}
    <section style={{ height: "100vh", display: "flex", alignItems: "flex-end" }}>
      <h1>Annual report</h1>
    </section>
    <p>The report starts on page two.</p>
  </article>,
  { margin: 0 },
);
```

Like `vh`, `vw`, `vmin`, and `vmax` resolve against the page area. In the `header` and `footer` bands, viewport units resolve against the full page.

## Widows and orphans

When a page break cuts a paragraph, at least `orphans` lines stay at the bottom of the page and at least `widows` lines move to the top of the next. Both default to 2, like Chromium. Set them to 1 to allow single lines:

```tsx twoslash title="Widows and orphans"
import { render } from "takumi-pdf";

const pdf = await render(
  // [!code highlight]
  <article style={{ widows: 3, orphans: 3 }}>
    A long report body wraps into many lines across the page boundary.
  </article>,
);
```

- Both properties inherit.
- If a paragraph is too short to satisfy both, `orphans` wins.
- A paragraph moves to the next page when the current page cannot hold the required lines.
- A requirement taller than a full page is relaxed.

## Split decorations

A box that crosses a page break slices its border and background by default, but `box-decoration-break: clone` gives each fragment complete decorations:

```tsx twoslash title="Split decorations"
import { render } from "takumi-pdf";

const pdf = await render(
  <section
    style={{
      border: "1px solid #d1d5db",
      borderRadius: 8,
      // [!code highlight]
      boxDecorationBreak: "clone",
    }}
  >
    Long content that continues on the next page.
  </section>,
);
```

## Repeated table headers and footers

A `<thead>` repeats at the top of each continuation page. A `<tfoot>` repeats below the last row on every page the table breaks across. Each section stays in one piece, with its spacing next to the body.

```tsx twoslash title="Repeated table headers and footers"
declare const rows: import("react").ReactNode;
declare const total: string;
// ---cut---
import { render } from "takumi-pdf";

const pdf = await render(
  <table>
    <thead>
      <tr>
        <th>Name</th>
        <th>Qty</th>
      </tr>
    </thead>
    <tbody>{rows}</tbody>
    <tfoot>
      <tr>
        <td>Total</td>
        <td>{total}</td>
      </tr>
    </tfoot>
  </table>,
);
```

A section repeats only when all of these hold:

- It has `break-inside: avoid`. `<thead>` and `<tfoot>` set it by default, as in Chromium.
- It is no taller than a quarter of the page area, matching Chromium.
- None of its cells has a `rowspan` that reaches into the body.

## Page ranges

`pageRanges` keeps only the listed pages, like a print dialog. Each entry is a 1-based page number or an inclusive span:

```tsx twoslash title="Page ranges"
declare const rows: import("react").ReactNode;
// ---cut---
import { render } from "takumi-pdf";

const pdf = await render(<main>{rows}</main>, {
  // [!code highlight]
  pageRanges: [1, { from: 4, to: 8 }, { from: 12 }],
});
```

An unset `from` starts at the first page, and an unset `to` runs to the last. The render fails if a range names page 0, runs backwards, or keeps no page. Layout and page counters still run over the whole document, so a kept page shows the numbers it has in full output, so page 4 of 12 still reads "Page 4 of 12". Links and outline entries that point at a dropped page are dropped with it.

## Watermarks

A `position: fixed` box paints on every page. It lays out against the page area, outside the content flow.

```tsx twoslash title="Watermarks"
import { render } from "takumi-pdf";

const pdf = await render(
  <main>
    <div
      style={{
        position: "fixed",
        inset: 0,
        display: "flex",
        alignItems: "center",
        justifyContent: "center",
      }}
    >
      <span style={{ fontSize: 96, color: "rgba(0,0,0,0.08)" }}>DRAFT</span>
    </div>
    <p>Long content that continues on the next page.</p>
  </main>,
);
```

<Callout type="warn">
  Keep the fixed box outside transformed or filtered ancestors. Such an ancestor contains the box,
  so the box paginates with it instead of repeating on every page.
</Callout>

To put the watermark behind content, give it a negative `z-index`. If the root background then covers it, set the page color with the `backgroundColor` option instead.
