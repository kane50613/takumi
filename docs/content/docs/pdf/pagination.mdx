Content flows across pages at the width available inside the margins. Use CSS break properties to start chapters, keep related content together, and control how paragraphs split. Percentage heights do not resolve in this mode because the content has no fixed height. Viewport units do: `vh` is the page area height, as in print media.

## Mixed page sizes

Use `sections` to append content with a different page size or orientation in one `render()` call. Each section starts on a new page and paginates at its own content width and height. The PDF writes the physical size into each page's `MediaBox`; it does not rotate portrait pages or merge separate PDFs.

```tsx twoslash title="Portrait report with a landscape appendix"
declare const report: import("react").ReactNode;
declare const ledger: import("react").ReactNode;
// ---cut---
import { render, PageNumber, TotalPages } from "takumi-pdf";

const pdf = await render(report, {
  size: "a4",
  footer: (
    <div>
      Page <PageNumber /> of <TotalPages />
    </div>
  ),
  // [!code highlight:6]
  sections: [
    { node: ledger, landscape: true, margin: 32 },
    { node: <p>Closing note, back on portrait A4.</p> },
    { node: <p>Custom paper.</p>, size: { width: 600, height: 400 } },
  ],
});
```

Each section accepts `node`, `size`, `landscape`, `margin`, `header`, and `footer`. Omitted geometry fields inherit the **document options**, not the preceding section. `landscape: false` explicitly selects the unswapped size. A supplied `margin` replaces the whole margin setting. Explicit dimensions use CSS pixels, like the document's `size`.

Headers and footers inherit too; pass `false` to remove one for a section. Document `pages.first`, `pages.last`, `pages.odd`, and `pages.even` rules still override these bands using document-wide page numbers.

`PageNumber`, `TotalPages`, target-page counters, page ranges, internal links, the outline, metadata, attachments, and the tagged structure tree belong to the whole document. A section can contain JSX, HTML (including its stylesheet), or a node tree. Fonts, images, and CSS are shared across sections. `sections` cannot be combined with `viewport`.

## Break properties

```tsx twoslash title="Break properties"
import { render } from "takumi-pdf";

const pdf = await render(
  <article>
    {/* [!code highlight:2] */}
    <h1 style={{ breakBefore: "page" }}>Chapter two</h1>
    <section style={{ breakInside: "avoid" }}>Keep this together.</section>
  </article>,
);
```

| Property                      | Effect                                                  |
| ----------------------------- | ------------------------------------------------------- |
| `break-before: page`          | Starts the element on a new page.                       |
| `break-after: page`           | Starts the following content on a new page.             |
| `break-inside: avoid`         | Keeps the element on one page when it fits.             |
| `box-decoration-break: clone` | Repeats borders and backgrounds on every page fragment. |

`break-inside: avoid` applies only when the box fits on a page. An oversized box can still split. Text lines, images, and transformed subtrees are kept together where possible.

## Full-page boxes

A `100vh` box fills one page inside the margins, and the next box starts on the following page. Use it for a cover or any page laid out by hand:

```tsx twoslash title="Full-page cover"
import { render } from "takumi-pdf";

const pdf = await render(
  <article>
    {/* [!code highlight] */}
    <section style={{ height: "100vh", display: "flex", alignItems: "flex-end" }}>
      <h1>Annual report</h1>
    </section>
    <p>The report starts on page two.</p>
  </article>,
  { margin: 0 },
);
```

`vw`, `vmin`, and `vmax` resolve against the same page area. In the `header` and `footer` bands they resolve against the full page.

## Widows and orphans

A cut through a paragraph keeps at least `orphans` lines at the bottom of the page and `widows` lines at the top of the next. Both default to 2, like Chromium. Set them to 1 to allow lone lines:

```tsx twoslash title="Widows and orphans"
import { render } from "takumi-pdf";

const pdf = await render(
  // [!code highlight]
  <article style={{ widows: 3, orphans: 3 }}>
    A long report body wraps into many lines across the page boundary.
  </article>,
);
```

Both properties inherit. If a paragraph is too short to satisfy both values, `orphans` takes priority. A paragraph moves to the next page when the current page cannot hold the required lines. A requirement larger than a full page is relaxed.

## Split decorations

A box that crosses a page break slices its border and background by default. Set `box-decoration-break: clone` to give each fragment complete decorations:

```tsx twoslash title="Split decorations"
import { render } from "takumi-pdf";

const pdf = await render(
  <section
    style={{
      border: "1px solid #d1d5db",
      borderRadius: 8,
      // [!code highlight]
      boxDecorationBreak: "clone",
    }}
  >
    Long content that continues on the next page.
  </section>,
);
```

## Repeated table headers and footers

Use `<thead>` for column headings that repeat at the top of continuation pages, and `<tfoot>` for rows that repeat below the last row of every page the table breaks across. Each stays together, including its spacing next to the body.

```tsx twoslash title="Repeated table headers and footers"
declare const rows: import("react").ReactNode;
declare const total: string;
// ---cut---
import { render } from "takumi-pdf";

const pdf = await render(
  <table>
    <thead>
      <tr>
        <th>Name</th>
        <th>Qty</th>
      </tr>
    </thead>
    <tbody>{rows}</tbody>
    <tfoot>
      <tr>
        <td>Total</td>
        <td>{total}</td>
      </tr>
    </tfoot>
  </table>,
);
```

A section repeats only with `break-inside: avoid`, which `<thead>` and `<tfoot>` set by default, as in Chrome. A header or footer taller than a quarter of the page does not repeat, matching Chromium. A header or footer cell whose `rowspan` reaches into the body suppresses repetition for that table.

## Page ranges

`pageRanges` keeps only the listed pages, like a print dialog. Each entry is a 1-based page number or an inclusive span:

```tsx twoslash title="Page ranges"
declare const rows: import("react").ReactNode;
// ---cut---
import { render } from "takumi-pdf";

const pdf = await render(<main>{rows}</main>, {
  // [!code highlight]
  pageRanges: [1, { from: 4, to: 8 }, { from: 12 }],
});
```

An unset `from` starts at the first page. An unset `to` runs to the last. Ranges that keep no page reject the render.

Layout and page counters still run over the whole document. A kept page shows the numbers it would in full output, so page 4 of 12 still reads "Page 4 of 12". Links and outline entries pointing at a dropped page are dropped with it.

## Watermarks

`position: fixed` paints a box on every page.
The box lays out against the page area.
It stays outside the content column.

```tsx twoslash title="Watermarks"
import { render } from "takumi-pdf";

const pdf = await render(
  <main>
    <div
      style={{
        position: "fixed",
        inset: 0,
        display: "flex",
        alignItems: "center",
        justifyContent: "center",
      }}
    >
      <span style={{ fontSize: 96, color: "rgba(0,0,0,0.08)" }}>DRAFT</span>
    </div>
    <p>Long content that continues on the next page.</p>
  </main>,
);
```

Place the fixed box outside transformed or filtered ancestors. Those ancestors contain the box, so it paginates with them instead of repeating independently.

Use a negative `z-index` to place the watermark behind content. Set the page color through `backgroundColor` if the root background would otherwise cover the watermark.
