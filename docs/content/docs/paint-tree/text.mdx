A text run is a stretch of text shaped with one font, size, and color. `<b>world</b>` inside a paragraph is its own run. Runs sit on the node that lays them out, in visual order.

## Place a run

A run's `x` and `y` are the start of its baseline, relative to the node's border box. `width` is its advance.

`transform` appears when `text-fit` scales the line. Apply it on top of the node's matrix before drawing at `x`, `y`.

```ts twoslash title="Draw every run"
import { paint } from "takumi-paint";

const tree = await paint("<p>hello <b>world</b></p>", { width: 400 });

function drawText(ctx: CanvasRenderingContext2D) {
  for (const { run, node } of tree.textRuns()) {
    ctx.setTransform(...node.matrix);
    if (run.transform) ctx.transform(...run.transform);
    ctx.font = `${run.font.weight} ${run.fontSize}px ${run.font.family}`;
    ctx.fillText(run.text, run.x, run.y);
  }
}
```

`tree.textRuns()` yields every run in paint order, paired with the node that paints it.

## Fonts

`run.font` describes the font instance the run was shaped with:

| Field                   | Value                                                         |
| ----------------------- | ------------------------------------------------------------- |
| `family`                | The family the face was registered under; absent when unnamed |
| `faceIndex`             | Index of the face within its collection                       |
| `weight`                | Weight class, with `wght` applied when the face is variable   |
| `style`                 | `normal`, `italic`, or `oblique`                              |
| `width`                 | Width as a percentage of normal                               |
| `variations`            | Variation coordinates the run was shaped at                   |
| `syntheticBoldWidth`    | Stroke width in px for synthetic bold                         |
| `syntheticObliqueAngle` | Synthetic oblique angle in degrees                            |

Runs shaped with the same face share one object from `tree.fonts`, so a font table keyed by object identity holds each face once.

## Glyphs

`run.glyphs` lists each glyph's `id` in the run's font and its offset from the run origin. Draw glyphs instead of `run.text` when the target API takes glyph ids, or when it must match the renderer's shaping exactly.

## Vertical metrics

| Field           | Value                                  |
| --------------- | -------------------------------------- |
| `ascent`        | Typographic ascent above the baseline  |
| `descent`       | Typographic descent below the baseline |
| `top`, `bottom` | `y - ascent` and `y + descent`         |
| `lineHeight`    | Height of the run's leaded box         |

Under `line-height: normal`, a run set in a fallback face grows `lineHeight` to that face's own height, the same way it grows the line.

## Lay the text out again

A PPTX slide does not take glyph positions. It takes a text box and paragraphs, then builds the lines from the font metrics. These values let a writer rebuild the paragraph:

| Value       | Where                                                       |
| ----------- | ----------------------------------------------------------- |
| Text box    | `node.contentBox`, relative to the node's border box        |
| Alignment   | `node.textAlign`, with `start` and `end` resolved to a side |
| Line height | `run.lineHeight`                                            |
| Tracking    | `run.letterSpacing`, already applied to the glyph positions |
| Font        | `run.font.family`, `run.font.weight`, `run.font.style`      |

```ts twoslash title="Collect paragraphs"
import { paint } from "takumi-paint";

const tree = await paint(
  `<div style="width: 400px; padding: 24px; text-align: center; line-height: 1.5">Quarterly review</div>`,
  { width: 400 },
);

const paragraphs = [...tree]
  .filter((node) => node.textRuns.length > 0)
  .map((node) => ({
    x: node.x + node.contentBox.x,
    y: node.y + node.contentBox.y,
    width: node.contentBox.width,
    align: node.textAlign,
    runs: node.textRuns.map((run) => ({
      text: run.text,
      family: run.font.family,
      weight: run.font.weight,
      size: run.fontSize,
      lineHeight: run.lineHeight,
      letterSpacing: run.letterSpacing,
    })),
  }));
```

`node.x + node.contentBox.x` is the text box's left edge on the canvas when the node has no `transform`.

## Decorations, strokes, and shadows

- `run.decorations` lists underline, overline, and line-through rectangles, each placed by its own `transform` in border-box space.
- `run.stroke` is the visible `-webkit-text-stroke`.
- `node.textShadows` apply under every run of the node, later-listed shadows lowest.

## Map a run to its source

`run.textByteRange` is the UTF-8 byte range of the run's text within the node's inline text. `run.spanId` names the inline span the run came from, so runs split from one span share it.
