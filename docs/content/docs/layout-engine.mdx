Takumi runs [Taffy](https://github.com/DioxusLabs/taffy) for Flexbox, Grid, and block layout. Tags keep their browser defaults: `<div>` is `block`, `<p>` has margins, `<h1>` is bold.

<Callout type="warning">
  Coming from [satori](https://github.com/vercel/satori)? Takumi follows the browser, not satori. It
  never forces `display: flex`, and `flex-direction` defaults to `row`. A bare `<div>` is a block
  until you set `display: flex`.
</Callout>

## Display

Supported values: `block`, `flex`, `inline-flex`, `grid`, `inline-grid`, `inline`, `inline-block`, `none`. They behave as they do in a browser.

## Sizing

Omit `width` or `height` and the node sizes to its content.

```tsx twoslash
import { ImageResponse } from "takumi-js/response";

export function GET() {
  return new ImageResponse(<List />, {
    width: 1200,
  });
}

function List() {
  const items = Array.from({ length: 5 }, (_, i) => i);

  return (
    <div style={{ width: "100%" }}>
      {items.map((item) => (
        <div key={item}>Item {item}.</div>
      ))}
    </div>
  );
}
```

Lengths take pixels, `%`, `auto`, `fr`, `vw` / `vh`, `em` / `rem`, and `calc()`, clamped by the `min-` and `max-` variants.

The `width` and `height` you pass to the render set the pixel canvas, but the root node won't fill it on its own. Give the root `width: 100%` and `height: 100%` for a full-bleed image.

An `<img>` measures to its intrinsic size unless you set `width` and `height`.

## Positioning

`relative`, `absolute`, `fixed`, and `z-index` work as in a browser. `fixed` resolves against the canvas.
