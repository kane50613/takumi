title: Void
description: Return Open Graph images from Void routes written in Hono JSX, on Cloudflare or on the Node.js target.
---

[Void](https://void.cloud) routes run on Hono. Takumi draws Hono JSX as the HTML that Hono's `c.html()` would send, so a route returns an `ImageResponse` with no adapter package. On Cloudflare, Takumi runs on its WebAssembly backend. On the Node.js target, it runs on its native addon.

<Steps>
  <Step>
    ### Install Takumi and Hono

    ```npm
    npm i takumi-js hono
    ```

  </Step>
  <Step>
    ### Use Hono's JSX in routes

    Skip this step if your app already sets `importSource` to `hono/jsx`. An app on React can keep React's JSX, which Takumi renders as well.

    ```ts title="vite.config.ts"
    import { defineConfig } from "vite-plus";
    import { voidPlugin } from "void";

    export default defineConfig({
      oxc: { jsx: { runtime: "automatic", importSource: "hono/jsx" } }, // [!code highlight]
      plugins: [voidPlugin()],
    });
    ```

  </Step>
  <Step>
    ### Create the route

    A handler can return a `Response`, so return the `ImageResponse` directly.

    ```tsx title="routes/og.tsx"
    import { ImageResponse } from "takumi-js/response";
    import { defineHandler } from "void";

    export const GET = defineHandler((c) => {
      const title = c.req.query("title") ?? "Hello from Void";

      return new ImageResponse(
        <div
          style={{
            display: "flex",
            alignItems: "center",
            justifyContent: "center",
            width: "100%",
            height: "100%",
            background: "#4f46e5",
          }}
        >
          <h1 style={{ fontSize: 72, color: "white" }}>{title}</h1>
        </div>,
        { width: 1200, height: 630 },
      );
    });
    ```

    Hono escapes `title` as it renders the JSX, so a request cannot inject markup through it.

  </Step>
  <Step>
    ### Request the image

    Run `npm run dev`, then open `/og?title=Hello`.

  </Step>
</Steps>

## Load data while rendering

An async component can fetch or query what the image shows. Takumi waits for it, as `c.html()` does, so a `Suspense` boundary shows its children, not its fallback. Context and `ErrorBoundary` work as they do in Hono too:

```tsx title="routes/og/[slug].tsx"
import { Suspense } from "hono/jsx/streaming";
import { ImageResponse } from "takumi-js/response";
import { defineHandler } from "void";

const Title = async ({ slug }: { slug: string }) => {
  const post = await fetch(`https://api.example.com/posts/${slug}`).then((res) => res.json());

  return <h1 style={{ fontSize: 72 }}>{post.title}</h1>;
};

export const GET = defineHandler((c) => {
  const slug = c.req.param("slug");

  if (!slug) {
    return c.notFound();
  }

  return new ImageResponse(
    <div style={{ display: "flex", width: "100%", height: "100%", padding: 64 }}>
      <Suspense fallback={<h1>Loading</h1>}>
        <Title slug={slug} />
      </Suspense>
    </div>,
    { width: 1200, height: 630 },
  );
});
```

Hono's `html` template from `hono/html` works too, with its values escaped and awaited.

## Draw text in other scripts

The built-in Geist font covers Latin text. Characters no font covers draw as boxes, and Takumi prints a warning that names them. To draw them, load a font only when the image needs it with `loadFallbackFonts`. This route downloads the Japanese characters of its title from Google Fonts:

```tsx title="routes/og.tsx"
import { googleFonts } from "takumi-js/helpers";
import { ImageResponse } from "takumi-js/response";
import { defineHandler } from "void";

export const GET = defineHandler((c) => {
  const title = c.req.query("title") ?? "こんにちは、Void";

  return new ImageResponse(<h1 style={{ fontSize: 72 }}>{title}</h1>, {
    width: 1200,
    height: 630,
    loadFallbackFonts: (characters) =>
      googleFonts({ families: ["Noto Sans JP"], text: characters.join("") }), // [!code highlight]
  });
});
```

Takumi keeps the files it downloads in a store that later renders share, so a later render that needs the same file skips the download. See [Fonts](/docs/fonts#load-fonts-for-missing-characters) for choosing families and handling fonts that fail to download.

## Deploy

On Cloudflare, `void deploy` bundles Takumi's WebAssembly binary into the Worker, where it makes up most of the size. See [Cloudflare Workers](/docs/frameworks/cloudflare-workers#size-and-limits) for its size and the limits to check.

On the [Node.js target](https://void.cloud/integrations/nodejs-bun-deno), keep `takumi-js` in your app's `dependencies`. The build then leaves `takumi-js` out of `dist/ssr`, and Node loads it from `node_modules` at runtime, with the native addon for the server's platform. Run `npm install` where the server runs, so it installs the addon for that platform rather than the one you built on.
